01

模型定制 · Nova Forge

让模型学会企业知识，又不忘掉原来的能力

PDF 先讲“灾难性遗忘”，再进入检查点与数据混合。关键不是把企业文档全部塞给模型，而是在可塑性与稳定性之间做可验证的取舍。

现场材料说什么

用中间检查点、持续预训练（CPT）、监督微调（SFT）和强化微调（RFT）进行领域适配，并同时观察通用能力回退。

官方文档校准

Nova Forge 提供开放训练检查点、Nova 精选数据混合、奖励函数与配方。数据混合比例没有固定答案，要以小规模对照实验寻找平衡。

企业决策问题

如果知识需要频繁更新，先考虑 RAG；只有当任务行为、领域语言或可验证推理需要改变时，才进入微调或 CPT。

训练方法怎么选

CPT 用于大量无标签领域语料；SFT 用高质量输入输出示例塑造任务行为；RFT 用可计算奖励优化多步决策。数据少、目标窄时优先参数高效微调；变化快、需要来源引用时优先 RAG。

02

评测闭环 · VOC / Benchmark

先把真实业务问题写进测试集，再谈模型排名

PDF 把客户之声（VOC）、场景 Benchmark 与 MMLU 放在一起。通用榜单只能作参照，真正的上线标准来自真实问法、边界案例与业务容错线。

能力层

推理、数学、代码、长上下文与指令遵循。

任务层

基于 VOC 的任务完成率、事实性与引用质量。

生产层

延迟、吞吐、成本、失败率与可观察性。

安全层

越权、敏感信息、提示注入与人工升级。

管理者要拿到什么

一张把业务损失、质量指标和成本放在一起的验收表；不能只拿一个“模型得分”做采购或上线决定。

03

AI 基础设施 · Neuron

把图像模型从“能运行”优化到“能稳定交付”

PDF 的 FLUX 与 Qwen Image Edit 案例聚焦并行策略、算子适配、显存和吞吐。Neuron 是框架与 AWS AI 芯片之间的编译、运行和分析软件栈。

1拆流水线识别文本编码、去噪网络、VAE 与后处理边界。
2编译模型控制输入形状，排查不支持算子和 CPU 回退。
3实测瓶颈分别测首张延迟、稳态吞吐、并发与内存。
4扩大规模让数据、张量或流水线并行匹配实例拓扑。
不要照抄现场数字

演讲中的性能结果依赖模型版本、输入尺寸、精度、实例和 Neuron SDK 版本。上线前必须依据当前支持矩阵重新验证。

04

企业数据 · S3 Vectors / RAG

把海量向量放在成本友好的专用存储里

PDF 把 S3 Vectors 定位为 Agent、RAG 和语义搜索的向量存储。官方文档强调免预置、按使用付费、S3 级弹性与持久性，以及面向不同查询频率的延迟区间。

S3 Vectors海量向量、长期保留、成本优先

向量存储桶 → 向量索引 → 带元数据的向量记录。

Bedrock Knowledge Bases托管 RAG、少搭管道

摄取、切分、嵌入、检索和生成形成托管流程。

OpenSearch低延迟、高 QPS、复杂搜索

适合混合搜索、聚合、分面和高级过滤。

数据边界先于向量化

原文档的权限不会自动变成向量权限。摄取前要保留数据分类、租户边界与删除机制，检索时按身份做元数据过滤。

05

生成式 AI 平台 · Amazon Bedrock

模型只是底层，平台价值在统一推理与治理

PDF 的模型墙是入口；Bedrock 把模型推理、Knowledge Bases、Agents、评测和 Guardrails 放进同一服务层，再由 IAM、KMS、CloudTrail 与网络控制包住治理边界。

应用与工作流业务界面 · 人工审批 · 结果交付
Agent 与知识Agents · Knowledge Bases · 检索引用
评测与保护Evaluation · Guardrails
模型推理统一 API · 容量与模型选择
云端治理IAM · KMS · CloudTrail · 网络边界
一条安全的 RAG 请求怎么走

应用先认证用户并判断其数据权限；输入接受必要检查后转换为查询向量；知识库只检索该用户有权访问的片段并保留来源；模型生成后再次应用 Guardrails；最后记录最少但足够的追踪信息，并避免把密钥或敏感正文写入日志。

06

Agent 生产化 · AgentCore

让 Agent 能被授权、观察、限制和接管

PDF 中的移动 Agent、自动化和供应链案例共同指向：Agent 不是一次模型调用。它会保留上下文、调用工具并代表用户行动，因此需要生产级运行边界。

Runtime

托管代理和工具的运行环境，支持会话隔离与长运行工作负载。

Memory

区分即时记忆、长期记忆、业务数据库与审计记录。

Gateway

把 Lambda 和 API 转成受管工具，集中施加策略。

Identity

协调 IAM、OAuth 与 API 密钥，缩小每次代理行动的权限。

Built-in tools

在隔离环境中提供浏览器和代码解释器能力。

Observability

通过 CloudWatch 与 OTEL 观察调用、延迟、错误、指标和追踪。
